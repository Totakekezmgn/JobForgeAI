# CODEX.md — Codex作業ルール

あなた(Codex)はJobForge AIの実装担当である。設計はSPEC.md、タスクはTASKS.mdを正とする。
設計判断はあなたの役割ではない。仕様の曖昧さを発見したら実装せず報告する。

## 作業の進め方
- 1回の作業では**1チケットだけ**実装する(TASKS.mdのID単位)
- 実装前に、チケットの「対象」に書かれた関連ファイルを必ず読む
- 出力は**変更ファイルの差分(diff)のみ**。無関係な整形・リネームを混ぜない
- 実装後に `npm run build` を実行する。lintスクリプトがあれば `npm run lint` も実行する
- 変更したファイル一覧と、TASKS.md / CHANGELOG.md の更新案を最後に出す
- ビルドが通らない状態で作業を終えない。通せない場合は理由と現状を報告する

## 禁止事項(違反は差し戻し)
- SPEC.mdに反する実装(特に「個人情報最小化」「検証分離」「未ログインでも動く」の3制約)
- `lib/serverAuth.ts` / `lib/authFetch.ts` / RLS関連の認証ロジックの変更・緩和・バイパス
  (チケットで明示的に指示された場合のみ可)
- クライアントから送られたuserIdを信用する実装
- APIキー・シークレット・個人情報のコード直書き、および .env系ファイルの変更・出力
- console.log等のログにES本文・面接回答全文・メールアドレスを出す実装
- 新しいnpmパッケージの追加(必要なら理由を添えて提案のみ行い、人間の承認を待つ)
- 既存UI・既存機能を壊す変更(既存の動作を変える場合はチケットに明記されている時のみ)
- localStorageキー名・選考ステータス名の変更(SPEC.md 4章が正)
- Stripe本番モードの有効化、デプロイの実行
- 「あとで直す」前提の危険な実装・TODOで認証を飛ばす実装

## 実装スタイル
- 既存コードの命名・構成・CSSクラス(globals.css)に合わせる。新規CSSは既存クラスで表現できない時のみ追加
- コメントは日本語で「なぜそうするか」を書く(whatの逐語訳コメントは不要)
- エラーは握りつぶさない。ユーザーに見えるメッセージは日本語で統一文言
  (未ログイン時:「ログインが必要です。/login からログインしてください。」)
- AI呼び出しを追加する場合は validate.ts の入力検証と checkAndCountUsage の無料枠消費を必ず通す

## 報告フォーマット(毎回これで終える)
1. 実装したチケットID
2. 変更ファイル一覧
3. 差分(diff)
4. build / lint の実行結果
5. 受け入れ条件のセルフチェック結果(各項目に○×)
6. TASKS.md / CHANGELOG.md 更新案
7. 気づいた問題・仕様の曖昧点(あれば。勝手に直さない)
